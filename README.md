# 가상 금융 업무 에이전트 (Virtual Bank Agent)

자연어 요청으로 계좌·카드 업무를 처리하는 LangGraph 기반 AI Agent 입니다.
조회는 바로 답하고, 데이터를 바꾸는 업무는 **본인 확인 → 처리안 → 승인(Human-in-the-Loop)** 을 거친 뒤에만 저장합니다.
금액·잔액·성공 여부는 LLM 이 아니라 Python 함수가 계산한 값을 그대로 보여 줍니다.

## 1. 실행 방법

**준비** : Python 3.13, [uv](https://docs.astral.sh/uv/), Gemini API 키

```bash
uv sync
```

`src/.env` 파일을 만들고 키를 넣습니다.

```
GEMINI_API_KEY=발급받은_키
```

**실행**

```bash
uv run python src/main.py
```

```bash
uv run python src/main.py --debug
```

- `--debug` 를 붙이면 실행 로그를 화면에도 띄웁니다. 로그는 항상 `logs/날짜.log` 에 남습니다.
- `exit` 또는 `종료` 로 끝냅니다.
- 처음 켜면 `data/initial_data.json`(원본)을 `data/data.json`(작업본)으로 복사합니다. 모든 변경은 작업본에만 저장합니다.
  처음 상태로 되돌리려면 `data/data.json` 을 지우고 다시 켜면 됩니다.
- **본인 확인** : 변경 업무와 카드 번호 조회에서 한 번 묻습니다(세션 동안 유지). 가상 사용자(user-001)의 PIN `1234` 를 입력하면 됩니다. (확인 스크립트와 같은 가상 값)
  (계좌 비밀번호·휴대전화번호·주민번호 뒷자리도 됩니다. 데이터 안의 값은 해시로 저장되어 있습니다)

**확인 스크립트** : 기능마다 입력을 자동으로 넣고 결과를 출력하는 스크립트가 있습니다. 대부분 Gemini 를 부르므로 키가 필요합니다.

```bash
uv run python 테스트/단계별/2-4_즉시이체_확인.py
```

- `테스트/단계별/` : 구현 단계(0-2 ~ 5-3)별 확인 28개
- `테스트/보완/` : 구현 뒤 보완한 기능과 버그 수정 확인 14개
- 스크립트는 시작·끝에 `data.json` 을 원본으로 되돌립니다.

## 2. 구조 한눈에

```
입력 → [분기 0] 멈춘 업무가 있나? ─ 있음 → 그 답으로 재개
                                  └ 없음 → rewrite("그 카드" → 이름) → 1단 supervisor
1단 supervisor : 계좌 / 카드 / 결과(처리 기록 조회) / 없음(안내)
2단 계좌 : 조회 · 거래내역 · 이체 · 설정          2단 카드 : 조회 · 설정 · 재발급 · 결제
3단 : 이체 / 계좌 설정 / 카드 설정 / 재발급 / 카드 요금
      extract(LLM 으로 값 뽑기) → check(검사) → [질문·번호 고르기] → 본인 확인
      → 처리안 → 승인(interrupt) → 해석(승인/거절/수정/취소) → 실행 → 기록 → 저장 → 안내
```

- 코드 : `src/agents/`(흐름, 층별 폴더) · `src/functions/`(계산) · `src/data_store.py`(파일) · `src/main.py`(입력 루프)
- 자세한 그래프와 분기 조건은 [최종 설계](docs/설계%20최종/최종_설계.md) 를 보세요.

## 4. 동작 확인 결과

아래는 확인 스크립트 42개를 모두 돌려 나온 실제 출력입니다. (2026-09-28, 정리 작업 뒤 전체 실행 : 42개 모두 오류 없이 끝남)

### 4.1 구현한 기능

| 기능 | 입력 → 결과 | 스크립트 |
|---|---|---|
| 1단 분류 | 계좌 3 · 카드 3 · 업무 아님 2 요청 → **8 / 8 맞음** | 단계별/1-2 |
| 즉시 이체 | "생활비에서 저축으로 10만원" → 처리안(출금 후 잔액 1,331,800원) → 승인 → 이체, 거래 내역 `tx-021` 출금 · `tx-022` 입금, 처리 기록 `req-0001 이체 완료` | 단계별/2-4 |
| 거절 | 처리안에 "거절" → "이체 요청을 진행하지 않았습니다. 바뀐 것은 없습니다." 잔액 그대로, 기록 `req-0002 이체 거절` | 단계별/2-3 |
| 조건부 이체 | "생활비에 40만원 남기고 나머지 저축" → 1,031,800원 이체, 생활비 잔액 400,000원 | 단계별/3-3 |
| 나눠 이체 + 수정 | 저축 20만 · 여행 자금 10만 → "저축은 5만원만" 수정 → 처리안 다시(총 150,000원) → 승인 → 두 곳 이체 | 단계별/3-4 |
| 예약 이체 | 예약 → 목록 `[예약]` → 시각이 지나 켜면 `[예약 이체 완료]` → 취소 `sch-002 [취소]` | 단계별/3-8 |
| 계좌 등록·삭제 | 등록 2건(`reg-003`, `reg-004`) · 중복 등록 거절 · 삭제 | 단계별/3-7 |
| 카드 설정 | 별칭 변경 · 비밀번호 변경(로그에 새 비밀번호 없음) · 해지 · 등록(`card-009`) | 단계별/4-4 |
| 재발급 | 분실 정지 카드 → 회사로 신청 `app-003 [접수]` → "재발급 됐어?" 에 처리 기록으로 답 | 단계별/4-5 |
| 정지 후 재발급 | 분실 신고 처리안 → 승인 1 → 재발급 처리안("앞 단계 : 분실 신고 완료") → 승인 2 | 단계별/4-7 |
| 카드 조회 (은행별) | "가상은행 카드" → 6장, 분실 정지 카드는 `(사용 불가)` / "우리은행 말고 다른 은행은?" → 우리은행을 빼고 은행별로 | 보완/은행별카드조회, 다른은행카드 |
| 요금 조회 | "카드값 얼마 내야 돼?" → 낼 돈이 남은 청구서 4건과 합계 | 단계별/4-8 |
| 도메인 반송 | 1단을 일부러 틀리게(카드 요청을 계좌로) → 반송 1회 → 카드로 처리 / 두 번째도 아니면 안내 | 단계별/5-3 |
| 카드값 결제 | 전체 결제 320,000원 → `paid`, 부분 결제 100,000원 → `partial` | 단계별/4-9 |
| 분할·일괄 | 3개월 분할 1회차 150,668원 · 일괄 4건 → 완료 3 / 실패 1(잔액 부족) / 미처리 0 | 단계별/4-10 |
| 분할 남은 회차 | 납부일이 지나면 2/3회 · 3/3회 자동 납부 → `분할 끝` | 보완/분할자동납부 |
| 실시간 스케줄러 | 입력 없이 기다리는 동안 예약 이체 · 분할 회차 실행, 다음 입력 때 결과 표시 | 보완/실시간스케줄러 |
| 후속 결과 조회 | "아까 이체 됐어?" → 처리 기록 `req-0001 이체 [완료]` 내용 / "오늘 처리한 거 다 보여줘" → 2건 | 단계별/5-1 |
| 대화 기억 | "그 카드 잠가줘" → "여행 카드 잠가줘", "거기서 저축으로 5만원" → "여행 자금에서 저축으로 5만원" | 보완/대화기억 |

### 4.2 직접 선정한 실패 상황

| 실패 상황 | 입력 → 결과 | 스크립트 |
|---|---|---|
| 음수 이체 | "생활비에서 저축으로 -1만원" → "이체 금액은 0원보다 커야 합니다." (처리안까지 가지 않음) | 단계별/2-4 |
| 잔액 부족 | 1억원 이체 → "잔액이 부족합니다. (잔액 1,331,800원 / 보낼 금액 100,000,000원)" | 단계별/2-4 |
| 승인 뒤 잔액이 바뀜 (재검증) | 처리안 뒤 잔액을 1,000원으로 바꾸고 승인 → 실행 직전 재검사에서 "잔액이 부족합니다" 로 이체하지 않음 | 단계별/2-4 |
| 남기면 보낼 금액이 없음 | 잔액 40만원에 "500만원 남기고 나머지" → "잔액이 400,000원이라 5,000,000원을 남기면 보낼 금액이 없습니다." | 단계별/3-3 |
| 저장 실패 | `data.json` 을 읽기 전용으로 바꾸고 승인 → 저장 3번 시도 후 "저장에 실패해 처리하지 못했습니다. 바뀐 것은 없습니다.", 처리 기록도 늘지 않음 (data_store 실패 경우 35가지는 0-3 에서 통과 35 / 실패 0) | 단계별/2-3, 0-3 |
