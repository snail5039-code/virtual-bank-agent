가상 금융 업무 에이전트 — 데이터 설명

data/initial_data.json    원본. 읽기만 한다. 절대 쓰지 않는다.
data/data.json            작업본. 모든 조회와 변경은 여기에서만 일어난다.
                          초기화하면 원본을 다시 복사해 이 파일을 되돌린다.

공통 규칙
  - 금액은 전부 원 단위 정수다.
  - 시각은 ISO 8601 + 09:00 형식이다.  예: 2026-09-20T18:00:00+09:00
  - 날짜는 YYYY-MM-DD 형식이다.
  - 값이 없으면 null 이다.
  - ID 로 서로를 가리킨다. 이름이 아니라 ID 로 연결한다.

==============================================================================
users        (3건)
==============================================================================

사람 정보. 본인 인증에 쓴다. 현재 사용자는 user-001 로 고정한다.

  owner_id             사람 식별자. 다른 배열이 이 값으로 주인을 가리킨다
  name                 이름. 타인 이체할 때 예금주 확인에 쓴다
  phone                휴대전화번호. 인증 수단
  ssn_tail             주민등록번호 뒷자리(SSN=주민번호, tail=뒷자리). 인증 수단
  pin                  간편 비밀번호 4자리. 앱 잠금 해제용. 인증 수단

==============================================================================
accounts        (5건)
==============================================================================

내 은행 계좌. 잔액이 실제로 여기서 오르내린다.

  account_id           계좌 식별자. 프로그램 내부용
  owner_id             계좌 주인
  nickname             계좌 별명. 사람이 부르는 이름. '생활비로 보내줘' 의 그것
  purpose              계좌 용도. 자유 입력. 중복 허용
  balance              현재 잔액
  bank_code            은행 코드
  bank_name            은행 이름
  account_number       계좌번호. 사람에게 보여주는 실제 번호
  account_password     계좌 비밀번호 4자리. 이체할 때 확인

==============================================================================
registered_accounts        (2건)
==============================================================================

이체 상대 계좌 주소록. 타행 계좌는 accounts 에 없으므로 여기에 적어 둔다.

  registered_id        등록 식별자
  owner_id             등록한 사람
  bank_name            상대 은행 이름
  account_number       상대 계좌번호
  holder_name          예금주 이름
  nickname             내가 붙인 이름. '동생 생활비' 처럼 부를 때 쓴다
  account_id           같은 은행이면 accounts 의 account_id. 타행이면 null

==============================================================================
cards        (8건)
==============================================================================

카드. status 가 카드 업무의 중심이다.

  card_id              카드 식별자
  owner_id             카드 주인
  name                 카드 이름. 사람이 부르는 이름
  account_id           이 카드를 쓰면 돈이 빠지는 계좌
  status               active 사용가능 / locked 일시잠금 / lost 분실정지 / cancelled 해지

  * lost 는 잠금 해제로 되돌릴 수 없다. cancelled 는 어떤 변경도 불가.
  card_number          카드 번호
  card_type            debit 체크카드(즉시 출금) / credit 신용카드(청구 후 결제)
  bank_code            은행 코드
  bank_name            은행 이름
  card_password        카드 비밀번호 4자리
  credit_limit         신용 한도. 체크카드는 null
  report_reason        정지 사유. 분실 / 도난 / 부정사용. 정지 전에는 null
  reported_at          정지 신고 시각. 정지 전에는 null

==============================================================================
transactions        (20건)
==============================================================================

계좌 입출금 기록. 잔액이 실제로 움직인 것만 남는다. 이체하면 출금 1건 + 입금 1건이 생긴다.

  transaction_id       거래 식별자
  owner_id             거래가 일어난 계좌의 주인
  account_id           거래가 일어난 계좌
  type                 deposit 입금 / withdrawal 출금
  amount               거래 금액. 입금 출금 모두 양수
  occurred_at          거래 시각
  card_id              체크카드로 긁었으면 그 카드. 계좌이체나 입금이면 null
  merchant             가맹점 이름. 돈을 쓴 가게. 가게 거래가 아니면 null

==============================================================================
card_usages        (11건)
==============================================================================

신용카드 이용 내역. 긁은 시점에는 계좌 잔액이 줄지 않는다. 청구서(card_statements)로 모였다가 결제일에 한 번에 빠진다.
transactions 와 섞으면 출금 합계와 실제 잔액이 맞지 않으므로 따로 둔다.

  usage_id             이용 식별자. card_statements.items 가 이 값을 가리킨다
  owner_id             카드 주인
  card_id              사용한 신용카드
  amount               이용 금액
  occurred_at          이용 시각
  merchant             가맹점 이름

==============================================================================
card_statements        (5건)
==============================================================================

신용카드 월별 청구서. 낼 돈.

  statement_id         청구 식별자
  card_id              청구 대상 카드
  owner_id             카드 주인
  billing_month        청구 월. YYYY-MM
  total_amount         청구 총액
  paid_amount          지금까지 납부한 금액
  remaining_amount     남은 금액 = total_amount - paid_amount
  due_date             결제일(납기일). 지나도 납부할 수 있다
  status               unpaid 미납 / partial 일부납부 / paid 완납
  items                이 청구에 들어간 card_usages 의 usage_id 목록. 명세서가 이걸 펼친다
  paid_at              마지막 납부 시각. 없으면 null
  paid_account         납부에 쓴 계좌. 없으면 null

==============================================================================
card_installments        (0건)
==============================================================================

할부(분할 결제). 결제할 때 만들어진다. 처음에는 비어 있다. 부분 결제와 다르다. 부분은 '지금 얼마만', 할부는 '앞으로 몇 번에'.

  installment_id       할부 식별자
  statement_id         대상 청구서
  card_id              대상 카드
  total_amount         할부 총액
  months               할부 개월 수
  paid_count           지금까지 낸 회차
  monthly_amount       회차당 금액
  status               진행중 / 완료

==============================================================================
scheduled_transfers        (0건)
==============================================================================

예약 이체 목록. 등록할 때 만들어진다. 처음에는 비어 있다. 예약 시각이 지나면 프로그램이 확인해서 실행한다.

  schedule_id          예약 식별자
  owner_id             예약한 사람
  from_account         출금 계좌
  to_account           입금 계좌
  amount               이체 금액
  scheduled_at         예약 시각
  status               예약 / 완료 / 취소 / 실패

==============================================================================
memberships        (2건)
==============================================================================

카드 멤버십. 조회만 하는 부가 정보.

  membership_id        멤버십 식별자
  owner_id             주인
  card_id              연결된 카드
  name                 멤버십 이름
  grade                등급
  points               보유 포인트

==============================================================================
addresses        (2건)
==============================================================================

재발급 카드를 받을 배송지. 집 / 회사 둘 중에서 고른다.

  address_id           배송지 식별자
  owner_id             주인
  label                배송지 이름. 집 / 회사
  address              주소

==============================================================================
reissue_applications        (2건)
==============================================================================

카드 재발급 신청. status 가 수정 가능 여부를 결정한다. 정지(lost)된 카드만 신청할 수 있다. 신청해도 원래 카드의 정지는
풀리지 않는다.

  application_id       신청 식별자
  owner_id             신청한 사람
  card_id              재발급 대상 카드
  address_id           받을 배송지
  status               received 접수(수정·취소 가능) / making 제작중(불가) / shipping
                       배송중(불가) / cancelled 취소됨
  created_at           신청 시각

==============================================================================
bills        (5건)
==============================================================================

공과금 청구서. 과제에서 제공한 초기 데이터. 청구서 카테고리를 구현 범위에서 제외했으므로 현재 아무 기능도 읽지 않는다. 나중에 확장할 수
있어 남겨 둔다.

  bill_id              청구서 식별자
  owner_id             주인
  name                 청구서 이름. 통신비 전기요금 등
  amount               납부할 금액
  due_date             납기일
  status               unpaid 미납 / paid 완납

==============================================================================
requests        (0건)
==============================================================================

업무 처리 기록. 처음에는 비어 있다. 업무를 하나 처리할 때마다 한 줄 남긴다. '아까 이체됐어?' 같은 후속 조회의 근거가 된다.

  request_id           요청 식별자
  owner_id             요청한 사람
  task_type            업무 종류. 이체 / 카드정지 / 결제 등
  target               처리 대상. 계좌나 카드 ID
  content              처리 내용
  status               성공 / 실패 / 취소
  result               결과나 실패 사유
  created_at           처리 시각
